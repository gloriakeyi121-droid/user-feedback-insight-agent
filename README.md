# 用户需求洞察 Agent

面向公开反馈分析的个人 AI 产品原型。导入 Excel，确认研究范围，生成可追溯的需求工作稿，支持人工审核与验证计划导出。

## 功能

- 反馈导入与字段检查。
- 单次分析与 Agent 工具调用两种模式，接入 DeepSeek 官方 API。
- 每条反馈分类、纳入依据与连续原文核对。
- 需求编辑、拆分、合并、证据调整及修改记录。
- 验证计划编辑、Markdown 报告导出、JSON 项目恢复。

Agent 可选择检索、读取、计数、引文检查和报告提交工具，最多 6 轮请求、20 次工具调用。验证计划初稿由固定规则生成，研究尚需人工执行。

## 本地运行

需要 Python 3.10 或以上。以下为 macOS/Linux 步骤，在项目目录运行：

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python feedback_app.py
```

Windows 可使用 `py -m venv .venv`，再运行 `.venv\Scripts\activate`，后续命令相同。

打开 http://127.0.0.1:8765/ 。终端进程需要保持运行；关闭后网页无法提交。按 Ctrl+C 停止。此地址只供本机使用，不是公开演示网址。

## 三分钟试用

1. 上传 `examples/synthetic_feedback.xlsx` 并点击“检查数据”。
2. 阅读默认问题及范围，确认是否符合目标。
3. 在页面填写 DeepSeek API Key 与账户可用的模型 ID，选择模式并开始分析。页面预填值来自开发时配置，是否可用以账户实际支持为准。
4. 查看分类、原文依据和执行记录，再编辑需求及验证计划。
5. 保存编辑后下载审核项目和报告。刷新后可在“继续已有审核”中导入项目 JSON。

示例中的三条反馈由人工构造，仅演示格式，example.com 链接不是实际反馈来源，不能作为效果评测。预期范围内 DEMO001 直接相关、DEMO003 间接相关、DEMO002 不相关；模型输出仍需审核。

## 数据格式

第一个工作表必须含 `feedback_id`、`title`、`content`、`source_url`。可附加 `created_at`、`collected_at`、`source_category`、`source_section`、`source_rank`。未知发布时间留空，不能用采集时间或评论时间代替。

## 密钥与费用

密钥在页面输入，不写入项目文件；也支持服务端 `DEEPSEEK_API_KEY` 环境变量。模型分析会将反馈文本发送给 DeepSeek 并产生 API 费用。不要上传不适合发送给该服务的数据。审核编辑和项目恢复不调用模型。请勿把密钥、环境文件或私人反馈提交到 GitHub。

## 已有评测与限制

真实 Goodnotes 案例中，group-review-v3 在六条已有回归样本上分类与参考标签全部吻合，形成四个需求组；该次运行耗时 15.64 秒，4 次请求，15,708 tokens。这不是独立盲测，也不能代表整体准确率。

较早版本一次同批对比：单次模式 4,268 tokens、12.46 秒；Agent 11,263 tokens、17.89 秒，分类均为 6/6。旧版数字来自操作者贴出的记录；不能与新版作严格因果比较。目前没有证明 Agent 优于单次模式，实际费用以账单为准。

引用匹配不能保证语义支持。真实报告中仍发现历史状态和来源概括问题，需要审核。当前导出的限制段沿用原始报告，修正说明应结合修改记录阅读。尚未完成真实目标用户试用和业务收益测量。

## 项目结构

- `feedback_app.py`：本地 HTTP 服务、Excel 读取与模型调用。
- `review.js`：审核工作稿、验证计划、保存恢复与导出。
- `examples/synthetic_feedback.xlsx`：合成演示数据。
- `requirements.txt`：运行依赖。

代码由 AI 辅助实现，项目负责人参与场景选择、数据准备、边界与参考答案确认、结果检查及产品取舍。项目未训练自有模型。该仓库包没有附带真实用户反馈全文或账户信息。

## 复现范围

可以复现功能流程和合成样例，模型输出会有波动。本包没有包含原六条真实评测输入，因此不能直接复现其准确率与用量；也未声明在其他操作系统完成测试。原开发环境使用 macOS 与 Python 3.13。
